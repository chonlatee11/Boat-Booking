<objective>
Close UAT gap G-01-7: "Logs for this span" in Grafana (Tempo → Loki) returns nothing for inner spans such as catalog UpsertBoat, even though the logs are in Loki with the right trace_id.

Root cause (verified in 01-UAT.md, trace 3feeb126): the Tempo datasource's tracesToLogsV2 sets no time shift, so Grafana searches Loki over exactly the clicked span's [start, end]. Service request logs are written by pkg/httpx/middleware.go requestLog at the END of the outer otelhttp server span, which is later than the end of inner child spans, so they fall outside the window.

Fix per D-51 (Grafana provisioning from files, trace↔log link): widen the window by one minute on each side. filterByTraceID: true stays, so results remain scoped to the trace.

Out of scope, on purpose: the dashboard half of the UAT report. The consumer-lag, outbox-backlog and oldest-age series exist and read a flat 0 on an idle system, which is correct. UAT test 8 is blocked on the merge to main and is not a gap.

Tracer note: this plan has one task. It is a config-only fix inside an observability stack that already works, so a separate tracer slice would tell us nothing new. The one task's verify covers the whole path: file → Grafana provisioning → Grafana API.

Output: one YAML edit, Grafana restarted and showing the new values through its API.
</objective>

  <action>
In the Tempo datasource (uid tempo), under jsonData.tracesToLogsV2, add two keys next to datasourceUid and filterByTraceID: spanStartTimeShift set to the quoted string '-1m' and spanEndTimeShift set to the quoted string '1m'. This implements D-51's trace↔log link for G-01-7. Keep filterByTraceID: true and datasourceUid: loki exactly as they are. Change nothing else in the file: no tags, no customQuery, and no edits to the Loki derivedFields or the Prometheus datasource.

Why ±1m: the request log is written a few hundred microseconds after inner spans end (see the root cause in 01-UAT.md). One minute covers that with a wide margin, and because the trace-id filter stays on, the wider window cannot mix in logs from other traces.

Apply it by restarting only the grafana container (boatbooking-grafana-1). Grafana re-reads its provisioning directory on start, and that directory is bind-mounted read-only from deploy/observability/grafana/provisioning. Do not run make down or up for this, and do not read .env: the verify command gets the admin password from the running container's environment and passes it to curl on stdin, not in argv (the same approach the Makefile ci-up target uses for Harbor).

Commit: fix(observability): widen Tempo trace-to-logs window so span logs resolve (G-01-7)
  </action>
