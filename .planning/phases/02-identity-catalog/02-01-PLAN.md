<objective>
Front-load the two human decisions this phase needs, then prove the new `pier_ids` claim end-to-end through the existing trust boundary: JWT (pkg/auth) -> Kong -> gateway re-verify -> `X-Pier-Ids` header -> `httpx.RequireInternal` -> `httpx.Claims` in the downstream request context.

Purpose: D-06 is a costly-to-reverse contract (token format, Kong/BFF header contract, every scoped query). Landing it first, alone, lets identity (02-02), catalog (02-03) and the gateway proxy (02-04) all build on one agreed shape in parallel. The checkpoints move all human interaction to the start of the phase so later waves run unattended.
Output: extended `pkg/auth` + `pkg/httpx` (claims + `ForwardClaims` moved into pkg/httpx), devtoken `-pier-ids`, whoami returning `pier_ids`, recorded storage + package decisions.
</objective>

## Phase Goal

**As a** customer, staff member or pier_admin, **I want to** sign in with a one-time code and (as an admin) manage operators, piers, routes, boats and prices, **so that** customers can browse the catalog publicly while every admin only ever touches their own operator's piers. *(Restatement of the ROADMAP Phase 2 goal.)*

This plan's slice: **As a** platform developer, **I want** a token's `pier_ids` to reach every service as a trusted claim, **so that** pier-level scoping (D-07) can be enforced server-side everywhere.

<assumption_delta_decision>
- Primary noun: `operator_id` stays the tenancy anchor; `pier_ids` is a refinement *inside* one operator (AND-combined in every query, D-07), not a replacement.
- Decision: `no-change` for the tenancy anchor — `pier_ids` is added alongside because it narrows, never widens, operator scope. super_admin bypasses both (D-06).
- What would force a promote: a user needing piers across two operators (multi-operator staff). Not in scope for v1.
</assumption_delta_decision>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01-01 | Spoofing / EoP | X-Pier-Ids header | high | mitigate | `httpx.ForwardClaims` deletes every inbound trusted header before setting verified values; `RequireInternal` only trusts headers alongside a constant-time-matched internal token |
| T-02-01-02 | Tampering | pier_ids JWT claim | high | mitigate | Claim lives inside the RS256-signed payload; Verify still enforces RS256 + issuer + exp (unchanged alg-confusion tests stay green) |

| T-02-SC | Tampering | go-redis, minio-go, maplibre-gl installs | high | mitigate | Task 2 blocking-human legitimacy checkpoint; exact versions pinned; installing plans carry a precondition on this approval |
