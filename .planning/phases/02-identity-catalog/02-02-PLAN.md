## Phase Goal

**As a** customer, staff member or pier_admin, **I want to** sign in with a one-time code and (as an admin) manage operators, piers, routes, boats and prices, **so that** customers can browse the catalog publicly while every admin only ever touches their own operator's piers. *(Restatement of the ROADMAP Phase 2 goal.)*

This plan's slice: **As a** customer, **I want to** type my email or phone and receive a one-time code that signs me in, **so that** I never create a password.

- Decision: `add-alongside` — `email` and `phone` columns side by side, at least one required (check constraint). Accepted debt: a person who signs in once by email and once by phone gets two customer accounts (no linking in v1).
- What would force a promote to a `user_identifiers(kind, value, user_id)` table: account linking or a third identifier (e.g. LINE login, GRW-01).

Design decisions (Claude's discretion per CONTEXT, recorded here):
- OTP lives ONLY in Valkey (no otps table): key `otp:code:{dh}` = hash {h: hex HMAC, a: attempts}, TTL 300 s; `otp:cooldown:{dh}` via SET NX EX 60; `otp:hourly:{dh}` via INCR + EXPIRE 3600 on first increment. `dh` = hex(HMAC-SHA256(OTP_HASH_SECRET, "dest:" + normalised destination)) so no raw email/phone appears in Valkey keys. Single-use = the winner of `DEL otp:code:{dh}` (returns 1) — atomic under concurrency.
- Code hash = hex(HMAC-SHA256(OTP_HASH_SECRET, "code:" + dh + ":" + code)), compared with `hmac.Equal` (Pitfall 4 pepper; research A2).
- One `notify.Sender` interface (method `SendOtp(ctx, to, code string) error`) is the D-01 seam for both channels: `SMTPSender` (net/smtp, dev email → Mailpit), `ResendSender` (net/http POST https://api.resend.com/emails — no SDK dependency), `DevSMSSender` (dev phone → Mailpit as an email to `<E.164 digits>@sms.local`, so phone OTPs are test-retrievable without ever being logged — answers research Open Question 1 / A3).
- Refresh tokens are opaque 32 random bytes (base64url); only sha256(token) is stored. Rotation + reuse detection arrive in 02-05.
- RPC names use `Otp` casing (`RequestOtp`, `VerifyOtp`) to satisfy buf STANDARD lint PascalCase.
</context>
