<objective>
Replace per-endpoint BFF handlers with two small, generic, allow-listed proxies so every admin RPC (catalog + identity user management) and every public catalog read is reachable through Kong without writing one gateway handler per RPC.

Purpose: D-18's admin app needs ~20 RPCs; hand-writing each in the BFF is pure boilerplate. One verified, spoof-stripping reverse proxy + one claim-less public reader keep the trust boundary in one reviewed place (AUTH-03) and deliver the CAT-06 public API surface (D-21) the moment catalog implements ListPiers/ListRoutes.
Output: `proxy.go` + tests, slimmer `bff.go`, gateway main wiring, updated Phase-1 scripts.
</objective>

## Phase Goal

**As a** customer, staff member or pier_admin, **I want to** sign in with a one-time code and (as an admin) manage operators, piers, routes, boats and prices, **so that** customers can browse the catalog publicly while every admin only ever touches their own operator's piers. *(Restatement of the ROADMAP Phase 2 goal.)*

This plan's slice: **As an** admin client, **I want** one authenticated URL shape for every catalog/identity admin RPC and **as a** visitor one unauthenticated URL per public list, **so that** the admin app and the future customer map need no new gateway code per feature.

Design notes:
- Kong already covers the new paths: `/api/v1/admin/*` falls under the JWT-verified `api` route; `/api/v1/public/*` under the unauthenticated `api-public` route. No Kong change in this plan.
- Connect unary over JSON = `POST /<package>.<Service>/<Method>` with `Content-Type: application/json`; connect-go returns errors as JSON `{code, message}` with the connect→HTTP status mapping (failed_precondition→400, resource_exhausted→429, permission_denied→403, not_found→404). Passthrough keeps those intact for the admin UI.
- connect-go's JSON codec omits empty repeated fields (`{}` instead of `{"piers":[]}`); every client treats a missing list as empty (apps/web boat-list already does `data?.boats ?? []`).
- Routes that call not-yet-implemented RPCs (ListRoutes until 02-06, UserService until 02-07) return the upstream's 404 — no gateway change is needed when they land.

## Trust Boundaries

| Boundary | Description |

| browser/Kong → gateway | Untrusted headers, cookies, bodies |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04-01 | Spoofing | client-supplied X-* headers through the proxy | high | mitigate | Rewrite deletes all trusted headers + Cookie/Authorization then ForwardClaims sets verified values; proxy_test asserts |
| T-02-04-02 | Elevation of Privilege | customer token reaching admin RPCs | high | mitigate | Gateway role gate (403) plus every catalog/identity admin RPC re-checks role (defense in depth) |
| T-02-04-03 | Tampering / SSRF | service or method path segment | high | mitigate | Exact-match service allow-list mapping to fixed URLs; method regex without `/` or `.`; path rebuilt, never concatenated from raw input |
| T-02-04-04 | Denial of Service | oversized bodies | medium | mitigate | 64 KiB MaxBytesReader; rejected before upstream |
| T-02-04-05 | Information Disclosure | claims leaking into public reads | high | mitigate | publicHandler builds a fresh request with only X-Internal-Token; TestPublicProxyIsClaimLess |
| T-02-04-06 | Elevation of Privilege | internal-only RPCs exposed via allow-listed service | medium | mitigate | Only CatalogService and UserService are routed (AuthService never is — its token-returning RPCs stay behind explicit cookie routes in 02-05); every RPC in the routed services enforces its own role check |
| T-02-04-07 | Repudiation | proxied request tracing | low | mitigate | otelhttp transport propagates traceparent; request log line per hop (existing Instrument) |
