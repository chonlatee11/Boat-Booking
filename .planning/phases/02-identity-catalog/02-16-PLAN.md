<objective>
Close the admin Piers-page halves of UAT gaps G-02-7 and G-02-8.

G-02-7 (blocker). Root cause from .planning/debug/pier-map-worker-crash.md, binding: handleLatChange/handleLngChange in map-picker.tsx only guard Number.isFinite. So a partial number input (reported by the DOM as "", which becomes 0) and transient out-of-range values (137) reach Marker.setLngLat. maplibre's LngLat constructor throws for |lat| > 90 inside a React effect, and with no error boundary the page is replaced. "Worker failed to load" is maplibre's generic label for that. Separately, map.on('error') latches tilesFailed for any error and never resets it, which is the spurious "โหลดแผนที่ไม่สำเร็จ" from UAT test 8.

G-02-8 (blocker), UI half. Root cause from .planning/debug/upsert-pier-failed-precondition.md, binding: (1) the create-pier operator select lists archived operators unmarked, so a super_admin picks one and the backend correctly rejects it (D-08) with a generic UI error. (2) The native time input in a 12h browser locale keeps its value as "" until AM/PM is committed, and hoursValid accepts both-empty, so typed hours are silently sent as empty strings. The backend message half is 02-15. It is not a dependency: this plan maps the error by code, not by message text.

Approach (smallest fix at the root): validate the lat/lng text before it ever becomes a value. Keep a draft string per input so partial typing is never clobbered, and send a value only when both drafts are valid. Make the tile-failure flag reset on success. Filter archived operators out of the select. Use locale-independent 24h HH:MM text for hours.

Out of scope, on purpose: an app-wide error.tsx boundary. With the input validated at the source, nothing throws, and adding one is not part of the root cause.

Tracer note: two fixes in two files of an existing, working Sheet. Each task's verify covers the admin build plus a real-browser human check. No separate tracer.
</objective>

  <action>
Per D-20 (click/drag marker plus manual lat/lng inputs, no geocoding) and gap G-02-7:

1. Change the onChange prop type to accept LatLng or undefined. pier-sheet passes setLocation, which already accepts undefined, so no caller change is needed. Map click and marker dragend keep sending real coordinates.

2. Add two draft string states, latText and lngText, initialized from value (String of each coordinate) or "". Render both inputs from these drafts. Switch both inputs to a text input with inputMode "decimal". The numeric input type reports a partially typed "13." to JS as an empty string, and that is the source of the jump-to-0 and the clobbered decimals. Keep the ids pier-lat/pier-lng and the Thai labels.

3. Add one module-level helper, parseCoord(text, limit). It returns the number only when the trimmed text is non-empty, Number(text) is finite, and its absolute value is at most limit (90 for lat, 180 for lng). Otherwise it returns null.

4. Replace handleLatChange/handleLngChange with handlers that store the raw text in the matching draft, parse both drafts (the new text for the edited field, the current draft for the other) and call onChange. They pass {lat, lng} only when both parse, else undefined. Drop the old THAILAND_CENTER fallback for the other coordinate. A half-entered pair is simply no location yet, so Save stays disabled in pier-sheet and saved coordinates can never differ from what the inputs show.

5. Sync the drafts when value changes from the map (click/drag). Use React's "store the previous prop in state and adjust during render" pattern: keep a prevValue state. When value is not identical to prevValue, set prevValue, and if value is defined, overwrite latText/lngText only when Number(draft) differs from the new coordinate. That keeps "13.70" as typed. Do not do this in a useEffect that calls setState; the react-hooks lint in eslint-config-next flags that.

6. Under each input, when its draft is non-empty but parseCoord returns null, set aria-invalid on the Input and render a FieldError. The copy is "ละติจูดต้องอยู่ระหว่าง -90 ถึง 90" for lat and "ลองจิจูดต้องอยู่ระหว่าง -180 ถึง 180" for lng.

7. Tile-failure flag, UI-SPEC E3 "โหลดแผนที่ไม่สำเร็จ": inside the mount effect, keep a local boolean tileLoaded = false. Register map.on('sourcedata') so that when the event has a tile, it sets tileLoaded = true and calls setTilesFailed(false). Change the existing error handler to call setTilesFailed(true) only while tileLoaded is still false. So the message shows when tiles or style are blocked from the start, and never latches on a partial or transient failure after tiles have rendered.

Leave the mount-only map creation, the marker-sync effect and the THAILAND_CENTER initial center as they are. Every value that reaches the marker-sync effect is now in range. Add no new dependency and no error boundary.
  </action>
