<objective>
Close the admin Routes-page UAT gaps G-02-12 and G-02-9.

G-02-12 (major). Root cause from .planning/debug/route-policy-false-invalid.md, binding: protojson omits int32 zero fields, so the mandatory 0-hour tier arrives from the API as an empty object. validatePolicy treats an absent field as a negative sentinel, while the inputs render it as 0, so a valid policy shows as invalid and Save is disabled in edit and return-route mode. Separately, the delete button renders on every tier whenever there is more than one. There is no last-tier guard. UAT test 10's pass on that point was wrong.

G-02-9 (major). Root cause from .planning/debug/duplicate-route-created.md, binding: the backend is correct (partial unique index plus a CHECK that pier_from differs from pier_to). The two "duplicate" rows were a route and its legitimate reverse between two different piers that are both named "Proof Pier". deploy/proof.sh hardcodes that pier name with no run suffix, and the admin pierName() and selects show only name_th, so same-named piers look identical.

Fix each at the one function every caller goes through: validatePolicy (used by both the editor and the Sheet's Save gate) and pierName (used by the list label and archive dialog, and now also by the selects). Plus a one-line proof.sh suffix. Out of scope: the separate per-page pierName helpers in boats/ and staff/, which are not part of these gaps.

Tracer note: small fixes to existing, working Sheets. Each task's verify covers the admin build (or make proof) plus a real-browser human check. No separate tracer.
</objective>
