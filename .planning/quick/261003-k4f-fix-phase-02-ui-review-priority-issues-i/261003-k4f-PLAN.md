Live observations at planning time (#3786 mutable-scope authority):
- `boats/page.tsx` lines 23-35 (`StatusBadge`) is the correct precedent. Active uses `className="border-transparent bg-green-100 text-green-800"`. Maintenance uses the orange equivalent.
- The four pages with a bare default-variant active badge are `operators/page.tsx:84`, `piers/page.tsx:115`, `routes/page.tsx:103` and `staff/page.tsx:223`. Their archived/disabled siblings use `variant="secondary"`, which is the UI-SPEC E2 "muted badge" and stays as is.
- These FieldErrors render without any gating: `pier-sheet.tsx` lines 193 (operator), 209 (nameTh) and 224 (nameEn), `boat-dialog.tsx:129` (name) and `staff-dialog.tsx:183` (name). Every other FieldError in these files is already gated on user input (hours, capacity, email, staff piers) and stays as is.
- `route-sheet.tsx` gates format errors on the field being non-empty (`&& durationMinutes`). That trick cannot work for a "required" error, because the error *is* emptiness. So required fields use a per-field touched flag. `operator-dialog.tsx` shows no error and only disables Save, which is also an accepted precedent.
- `NativeSelect` (`components/ui/native-select.tsx`) spreads `...props` onto the `<select>`, so its `onChange` handler works as usual.
- The same 8-character id-prefix fallback exists in three sibling helpers besides the one named in the ticket: `staff/queries.ts` `pierName` (line 72) and `operatorName` (line 66), and `routes/queries.ts` `pierName` (line 68). They leak the same raw UUID on the Staff and Routes pages, so Task 3 fixes all four (root cause, not one symptom).
- Root cause of the "00000000" in the Boats screenshot: these are Phase-1 legacy boats. Their nullable `home_pier_id` (migration 00007) is serialized by catalog as the nil-UUID string (`services/catalog/internal/app/boat.go:195`, `b.HomePierID.String()`). The `!id` guard does not catch that string, so it falls through to the fallback. With the Thai fallback these rows read "ไม่พบท่าเรือ". That is accurate (there is no pier) and nudges the admin to assign one. Do not special-case the nil UUID. The backend change is out of this admin-only scope.
- UI-SPEC Copywriting Contract (02-UI-SPEC.md lines ~115-145) has no wording for "pier/operator not found". Use "ไม่พบท่าเรือ", as suggested in the task description and UI-REVIEW, and "ไม่พบผู้ประกอบการ" by analogy.
- `npm --prefix apps/admin run format:check` already warns on `money.test.ts` and `api.test.ts` (pre-existing, not ours). The verify steps therefore run prettier only on the touched files.
